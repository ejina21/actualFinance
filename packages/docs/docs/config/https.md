title: Активация HTTPS
---

Вам нужно будет включить HTTPS на вашем сервере, чтобы безопасно использовать все функции Actual. **Вам не нужно следовать этим шагам** Если вы запускаете сервер на своем компьютере и получаете к нему доступ только через `localhost`Или если вы используете облачный провайдер, который обрабатывает HTTPS для вас.

## 1.Приобретите сертификат для использования на вашем сервере {#1-acquire-a-certificate-to-use-on-your-server}

Есть два способа сделать это, и оба относятся к не разоблачению фактического в Интернете. [Использование обратного прокси](./reverse-proxies.md).

### Используйте самоподписанный сертификат {#use-a-self-signed-certificate}

Используйте самоподписанный сертификат. Это самый простой способ заставить работать HTTPS, но это заставит ваш браузер отобразить предупреждение о том, что сертификат недействителен. Кроме того, если кто-то получит доступ к этому сертификату, он может перехватить самый безопасный трафик на вашем компьютере.

- Инструмент командной строки как [мккерт](https://github.com/FiloSottile/mkcert) Можно автоматизировать этот процесс.
- Альтернативно, вы можете вручную генерировать сертификаты. Установите OpenSSL для своей операционной системы, а затем запустите `openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout selfhost.key -out selfhost.crt` в терминале для генерации сертификата и приватного ключа вам нужно будет ввести двухбуквенный код страны, чтобы получить `.crt` файл должен быть сгенерирован, но вы можете оставить остальные поля пустыми (просто нажмите введите в каждой подсказке). `selfhost.key` и `selfhost.crt` Файлы в место, доступное фактическому серверу.
- При использовании самоподписанного сертификата вам может потребоваться обновить команду проверки здоровья в файле docker-compose.yml, чтобы убедиться, что он доверяет сертификату. `NODE_EXTRA_CA_CERTS=/data/selfhost.crt` Переменная среда для команды проверки здоровья:

  ```yaml
  test:
    [
      'CMD-SHELL',
      'NODE_EXTRA_CA_CERTS=/data/selfhost.crt node src/scripts/health-check.js',
    ]
  ```

### Получить сертификат, не выходя в интернет {#obtain-a-certificate-without-exposing-to-the-internet}

Используйте такую услугу, как [Хвостовой масштаб](https://tailscale.com/kb/1153/enabling-https/) или [Кэдди](https://caddyserver.com/docs/automatic-https#dns-challenge) Это позволяет вам создать действительный сертификат HTTPS без необходимости подвергать ваш сервер более широкому доступу в Интернет.

## 2.Настройка фактического использования сертификата {#2-configure-actual-to-use-the-certificate}

Как только у вас будет сертификат, вам нужно будет настроить Actual, чтобы использовать его. Есть два способа сделать это:

### Конфигурирование с `config.json` {#configuring-with-configjson}

Создать `config.json` файл в той же папке, где вы запускаете сервер фактической синхронизации. [Строительство из источника](../install/build-from-source.md) Это будет в `packages/sync-server/`Проложите путь к `.key` и `.crt` Примечание: если вы используете Docker или аналогичную среду контейнера, убедитесь, что пути доступны для контейнера.

Если используется контейнер Docker, эта папка `/data` Если вы установили объем для контейнера, папка на хосте, где `/data` Это место, где вы можете разместить `config.json` Файл.

`config.json`:

```json
{
  "https": {
    "key": "/data/selfhost.key",
    "cert": "/data/selfhost.crt"
  }
}
```

Если вы используете MacOS*Никс-ориентированные системы
в терминальной пасте следующее. Это создаст `config.json` в текущем каталоге

```zsh
cat <<"EOF" | tee config.json
{
  "https": {
    "key": "/data/selfhost.key",
    "cert": "/data/selfhost.crt"
  }
}
EOF
```

### Конфигурирование с переменными среды {#configuring-with-environment-variables}

Если вы не можете легко создавать новые файлы, вы также можете настроить HTTPS с помощью переменных среды. `ACTUAL_HTTPS_KEY` и `ACTUAL_HTTPS_CERT` переменные среды к содержанию `.key` и `.crt` Если вы не можете включить новые линии в переменные значения среды, вы можете заменить любые новые линии на `\n` Actual автоматически преобразует их обратно в новые линии.

### Настройка приложения Desktop {#configuring-the-desktop-app}

Чтобы настроить настольное приложение, выполните эти шаги на Где сервер?_ Экран.

1. Введите URL вашего сервера и нажмите OK.
2. Если вы видите сообщение об ошибке с просьбой выбрать сертификат, выберите соответствующий сертификат и попробуйте еще раз.

**Примечание:** Если вы создали свой сертификат, используя [мккерт](https://github.com/FiloSottile/mkcert), указать корневой сертификат CA - не тот сертификат, на который указывает ваш сервер.

1. Запускай команду `mkcert -CAROOT` Найти каталог корневого сертификата.
2. Перейдите в этот каталог, чтобы найти `rootCA.pem` сертификат
3. Укажите `rootCA.pem` Сертификат в настольном приложении.

## 3 Тестирование HTTPS {#3-test-https}

После того, как вы приобрели сертификат и настроили Actual для его использования, попробуйте получить доступ к вашему экземпляру, гарантируя, что вы используете его. `https`Рекомендуется также повторно ввести URL-адрес на ваш сервер или сделать новую вкладку / окно вместо обновления страницы, где вы увидели ошибку.
