# Частые вопросы {#frequently-asked-questions}

## Можно ли пользоваться Actual на телефоне?

Прежние официальные мобильные приложения больше не поддерживаются. Веб-версия Actual адаптирована для телефона: её можно добавить на главный экран как прогрессивное веб-приложение (PWA). Существуют и неофициальные приложения сообщества; они перечислены в разделе [«Проекты сообщества»](community-repos.md).

## Можно ли автоматически получать операции из банка?

Да, для некоторых банков доступна [синхронизация](./advanced/bank-sync.md). При первой настройке проще начать с недавней даты: создайте счёт с правильным начальным остатком, затем подключите банк. Тогда будут загружаться только операции после этой даты, а сверка займёт меньше времени.

## Как перенести бюджет из старого приложения Actual?

Прежний облачный сервис по подписке закрыт в 2024 году. Если вы всё ещё используете старое приложение Actual для компьютера, следуйте [инструкции по переносу](./migration/index.md#migration-from-the-old-actual-budget-desktop-app).

## Как обновить Actual?

Способ зависит от установки:

- PikaPods обычно обновляет образ примерно через неделю после выпуска новой версии.
- Для Docker с каждым выпуском публикуется новый образ.
- Для Fly.io есть [отдельная инструкция](./install/fly.md#updating-actual).

## Как учитывать кредитную карту, которую я полностью погашаю?

Actual считает кредитную карту счётом с отрицательным остатком. Для бюджета важна общая сумма денег: наличные и остатки на обычных счетах за вычетом долга по карте. Покупка по карте уменьшает доступную сумму в соответствующей категории. Само погашение карты — перевод между счетами, поэтому общий бюджет не меняется.

Если долг по карте нельзя погасить полностью, часть обязательства нужно учесть в отдельной категории. Подробнее см. раздел [«Кредитные карты»](./budgeting/credit-cards/index.md).

## Почему файл бюджета стал намного меньше?

Обычно Actual хранит историю изменений: добавления операций, изменения получателей, заметок, правил и других данных. Поэтому файл постепенно растёт.

После сброса синхронизации или экспорта с повторным импортом Actual объединяет накопленные изменения. Файл может заметно уменьшиться — это нормальное поведение.

## Что означает ошибка `PayloadTooLargeError: request entity too large`?

Размер загружаемого файла может превышать ограничение Actual или вашего сервера, обратного прокси либо хостинга. Лимиты Actual задаются переменными окружения:

- `ACTUAL_UPLOAD_FILE_SIZE_LIMIT_MB` — обычные загрузки, по умолчанию 20 МБ;
- `ACTUAL_UPLOAD_FILE_SYNC_SIZE_LIMIT_MB` — файлы синхронизации, по умолчанию 20 МБ;
- `ACTUAL_UPLOAD_SYNC_ENCRYPTED_FILE_SYNC_SIZE_LIMIT_MB` — зашифрованные файлы синхронизации, по умолчанию 50 МБ.

Если файл больше, увеличьте соответствующий лимит. Проверьте также ограничения обратного прокси, например `client_max_body_size` в Nginx.

## Есть ли у Actual API?

Да. Пакет API позволяет работать с бюджетом программно. Он запускает клиентскую часть без интерфейса и выполняет многие действия, доступные в приложении. Это не набор обычных REST-адресов: основная база Actual хранится локально, а сервер синхронизации передаёт изменения между устройствами. Подробнее см. [документацию API](./api/index.md).
